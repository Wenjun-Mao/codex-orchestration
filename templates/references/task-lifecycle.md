# Task Lifecycle

1. **Admit:** bind objective, authority, baseline, and exclusions.
2. **Map:** validate dependencies, write ownership, resources, and gates.
3. **Launch:** persist a creation operation, create the exact requested task
   kind before its deadline, pass resolved `model` and `reasoning_effort` as
   actual host arguments, then inspect and reconcile ID/title/kind/visibility.
4. **Execute:** remain inside packet ownership and verify proportionally.
5. **Signal:** Steer urgent conditions; persist and queue one ordinary terminal
   callback.
6. **Integrate:** observe the callback under the current recipient generation,
   authenticate, review, merge serially, and reprove combined behavior.
7. **Close:** consume the callback exactly once, release resources, archive appropriate task
   threads when the host permits it, and audit stale state.

Thread creation, archiving, deletion, and host-specific role binding are
capabilities, not assumptions. Record what the current session actually
exposes.
