# Task Lifecycle

1. **Admit:** bind objective, authority, baseline, and exclusions.
2. **Map:** validate dependencies, write ownership, resources, and gates.
3. **Launch:** create a separate task from a validated packet when capability is
   available, passing its resolved `model` and `reasoning_effort` as actual host
   creation arguments; otherwise hand the packet to a capable session.
4. **Execute:** remain inside packet ownership and verify proportionally.
5. **Signal:** Steer urgent conditions; queue one ordinary terminal callback.
6. **Integrate:** authenticate, review, merge serially, and reprove combined
   behavior.
7. **Close:** consume the callback, release resources, archive appropriate task
   threads when the host permits it, and audit stale state.

Thread creation, archiving, deletion, and host-specific role binding are
capabilities, not assumptions. Record what the current session actually
exposes.
