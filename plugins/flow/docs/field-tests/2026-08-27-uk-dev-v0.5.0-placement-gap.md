# UK Dev v0.5.0 placement-evidence pilot

## Scope

This held-out pilot exercised canonical package revision `dacf726` in an
isolated UK Dev adoption branch at `4de2efa`. Installation was clean: the root
AGENTS file remained byte-identical at 49 lines, and canonical check, pinned
doctor, and the repository's legacy process validator passed.

The coordinator made one Desktop `create_thread` call for a visible
Terra/xhigh host worktree, explicitly targeting the saved UK Dev project and
the v0.5 adoption branch. The task received only the no-action bootstrap.

## Stop result

Desktop created the expected titled task and a pristine UK Dev worktree at the
exact baseline. Post-create list/read surfaces returned a null or absent project
placement field, as they also do for other known project-backed archived tasks.
The task operation had no requested-versus-observed project-placement field, so
the pilot could not preserve the distinction between:

- the exact project target accepted by the host call;
- an independently observed project assignment; and
- a real non-null mismatch.

The coordinator stopped before Git binding, objective release, repository work,
or callback delivery. The bootstrap task was archived and its independently
verified clean detached worktree was removed without force.

## Cleanup finding

The operation had to remain `observed` to preserve its exact host object and
path. After archival and removal, doctor and cleanup still reported an observed
unbound worktree at the absent path. v0.5.0 had no terminal disposition for an
object rejected before Git binding and objective release.

## Interpretation

- Plugin-first installation passed.
- Actual wrong-project placement was not established.
- Same-project task release remained unaccepted because placement evidence was
  not modeled.
- The combined placement-evidence and terminal pre-release cleanup gap is the
  source for ADR 0011 and the v0.5.1 checkpoint.
