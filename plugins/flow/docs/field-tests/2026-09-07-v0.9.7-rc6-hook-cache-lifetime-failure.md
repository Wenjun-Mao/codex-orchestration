# v0.9.7 RC6 hook cache-lifetime failure

## Outcome

RC6 did not pass the required install-to-final-before-reload reporting gate.
Stable promotion remained withheld, the lost final was not replayed, and no
replacement canary was started from this failed state.

## Observed evidence

- The Codex Hooks panel reported `Stop / Queueing authenticated task report /
  hook exited with code 1` for turn
  `01a079d4-39f1-7391-8ae2-244d5e8b992e`.
- The session record retained that final, but the active route
  `report-route-v1-0db4991836923128d7f1d599212ba154cd943140a035a0c8964076fe1b552cf2`
  had no capture or submission for the turn.
- The loaded hook definition invoked
  `node "$PLUGIN_ROOT/bin/codex-flow-report-hook.mjs"` from the v0.9.6 plugin
  root. The RC6 installation had removed that v0.9.6 cache directory.
- Reproducing that exact launcher path with empty input produced zero stdout,
  Node `MODULE_NOT_FOUND`, and exit code 1. The referenced entrypoint was
  absent. This proves the failure mechanism and matches the observed exit code;
  it does not recover the original hook stderr, which the available UI and
  persisted logs did not expose.
- The retained v0.9.6 backup's reporter-file SHA-256 values matched the active
  locator's immutable reporter authority, ruling out an ordinary reporter-byte
  mismatch before cache removal.

## Root cause and correction

The route contract outlived its executable location. Codex plugin upgrades
remove older version directories, but already-loaded tasks may still emit a
final before reload. Binding reporter hashes while launching directly from the
shorter-lived installed cache left no executable capable of checking those
hashes.

The correction belongs at reporter lifetime, not queue handling. Registration
now stages a complete content-addressed reporter runtime in sender-scoped,
repository-owned locator state. An immutable launcher installed in
`PLUGIN_DATA` authenticates that runtime before every completion. Exact locator
retirement removes the staged runtime. No report replay, tolerant newer-runtime
fallback, mutable latest pointer, historical-state migration, or queue redesign
is added.

## Required follow-up gates

- Focused regression: remove the registering package, execute the stable
  launcher, and prove exact final capture/submission from the staged runtime.
- Prove a task with no registered route remains a harmless no-op.
- Prove locator retirement removes its sender-scoped runtime.
- Install the next required candidate over a loaded prior candidate and observe
  a real final reach the director before reload.
- Only after the corrected live canary and stable repetition pass may v0.9.7 be
  promoted.
