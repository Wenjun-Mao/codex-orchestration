## Thread-spawn completion mismatch and correction

The first real App-created sender completed with the exact three-line Unicode
final, but no report record appeared. Its session metadata identified it as an
`agent_created_thread`. Current Codex source maps a thread-spawn child's final
turn to `SubagentStop`, while independently opened root tasks use `Stop`. The
RC.1 manifest declared only `Stop`, and its handler rejected any other event.

This was a hook event-contract defect, not a queue or locator failure. RC.2
declares both native completion events and routes them through the same bounded
entrypoint. `SubagentStop` additionally requires `agent_id` to equal the routed
session identity. Focused tests preserve exact multiline Unicode capture and
reject a mismatched subagent identity without a queue attempt.

RC.2 then failed the current supported plugin preflight because its manifest
still declared the obsolete `hooks` key inherited from RC.1. The supported
ingestion contract discovers `hooks/hooks.json` by convention and rejects that
manifest field. RC.3 removes the field while retaining and validating the exact
hook file. This corrects the package boundary instead of bypassing validation.

The first trusted RC.3 thread-spawn event then captured the exact multiline
Unicode final but retained an ambiguous `producer-contract` submission. Its
diagnostic detail digest exactly matched the handler's bounded exception shape.
A separate real App-server probe accepted a 64-hex delivery key. Source review
showed that the handler passed the prefixed `report-record-v1-...` ID to the
adapter's digest-only delivery-key input. RC.4 passes the SHA-256 digest of that
persisted report ID and tests the caller-to-adapter mapping directly.

## Packaging identity failure and correction

The first personal-marketplace RC install used the generic plugin-development
cache-buster helper. That helper changed only `.codex-plugin/plugin.json` from
`0.9.3-rc.1` to `0.9.3-rc.1+codex.<timestamp>`, while `package.json` and the
runtime constant remained `0.9.3-rc.1`.

`refresh inspect` rejected the candidate before admission:

```text
Installed codex-orchestration package metadata must exactly match version 0.9.3-rc.1
```

This was a distribution-shape error, not a missing-trust signal. Flow's exact
package/plugin/runtime equality is intentional authority and was preserved.
The correction is to install the exact extracted RC artifact under the exact
`0.9.3-rc.1` identity; Flow release candidates must not use a manifest-only
cache-buster. A focused CLI regression now rejects that mismatch.
