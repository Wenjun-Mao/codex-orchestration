# v0.9.11 RC2 assignment-only registration failure

## Outcome

RC2 was not promoted. A disposable live canary preserved completed local work
across refresh, then stopped before creating an executor because coordinator
report-route registration rejected its retained worktree. A source correction
is available for review, but no replacement candidate has been staged or
installed.

The failed repository state is preserved locally for an exact, separately
approved unplug. The next live gate is a fresh original local-A to dependent-B
journey, not the baseline-only successor followed by an extra child.

## Failed boundaries and causes

- The first semantic-resume preparation attempted to discard completed local
  work. Refresh rejected that request before mutation because unfinished-task
  decision coverage did not match the requested target. The corrected
  preparation preserved local A and replaced only B.
- The corrected refresh and run activation succeeded. Coordinator route
  registration then persisted an assignment but rejected iteration membership
  with `Iteration worktree is shared by another persisted member`.
- The ownership classifier required predecessor and successor
  `repository_digest` values to be equal. That digest hashes the full repository
  snapshot, including revision. Completed local A had lawfully advanced the
  retained coordinator branch, so the digest changed while the canonical Git
  common directory, worktree, branch, host, task, sender, recipient, and
  reporting ownership remained the same.
- A corrected source entrypoint could not recover the active run. Runtime
  pinning rejected its bundle
  `9dbeb2553f5f9cf2e83af343f30aadeac5ef36de0424187bdb6814f1d645a581`
  in favor of the run-bound RC2 bundle
  `468c7d2af7545b92024f50c996990fa8108f78320a1c35669ee8b885069b71ef`
  before mutation. The pinned runtime contains the original classifier and
  deterministically repeats the rejection.

## Partial-registration dead end

The active disposable run has one open assignment record and no corresponding
iteration, report route, locator, or executor task. Normal cancellation cannot
settle this shape because cancellation requires the missing iteration and
route. Successor installation must not silently replace the run-bound runtime,
and the preserved RC2 bundle must not be patched. The approved recovery is an
evidence-bound repository unplug and clean start, kept separate from source
delivery.

## Changed and unchanged contracts

The source correction classifies stable assignment ownership by the already
authenticated canonical repository location, exact worktree and branch, host,
task, reporting parent, sender, and recipient. The revision-bearing repository
digest remains exact run evidence but is no longer treated as cross-assignment
repository identity. Cancellation ordering and exact terminal locator
retirement remain required, so unrelated or unsettled owners still fail closed.

No compatibility recovery command was added. Assignment-only cancellation is
still unsupported, the failed RC2 run remains unchanged pending exact unplug
approval, and the real dependent-executor App gate remains unproven.

## What verification covered

- The focused retained-successor and frozen RC1-to-current regressions passed
  2/2 in `8575.182125 ms`. They cover a revision-changing retained branch,
  public assignment-only replay that preserves the original creation time, and
  exact frozen-RC1 successor admission and reclamation.
- The affected assignment, coordinator, refresh, reporting, and release suite
  passed 80/80 with exit 0.
- The full `npm test` run completed with exit 0.
- `npm run validate` passed all 32 schemas and 46 classified modules.
- `git diff --check` passed.

These tests did not exercise the run-bound CLI recovery of this malformed
partial shape; the live probe demonstrated that boundary instead. They also do
not replace the missing real App proof that a dependent executor receives the
persisted local-A authority.

## Evidence access limitations

The exact RC1 namespace, RC2 Flow-state snapshot, transition outputs, task
history, and command diagnostics remain local release evidence. They are not
tracked because they contain machine-specific paths and workflow payloads; the
temporary transition-output directory is also not durable release storage. The
RC2 Flow-state archive contains 190 entries and 2,065,408 bytes, with SHA-256
`0c13d4f718a287ca24c0ed31566ef606fc3c58fd74dcad7485099ca089ed6cd3`.
No raw sessions, private task payloads, or wholesale `.git` evidence are
published by this note.
