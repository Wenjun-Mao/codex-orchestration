## Use: three amendments to the existing verification scope

1. **Multiple settled namespaces, including candidate-produced history.** Both
   reviewers identify the gap: the local journey creates multiple runs in one
   old namespace, but the stable live gate encounters retained RC4 history plus
   the completed new RC namespace. Extend the same local fixture through a later
   consumer using intended stable contents/identity before publication, with both
   old namespaces intact. Prove public inspection, activation, assignment/reporting
   readiness and useful work. Keep the original released producer genuinely frozen;
   a simulated later package is not installed-stable proof. Explicitly include
   candidate-emitted records in the supported consumer contract. Fully settled
   namespaces may coexist within bounds; competing unresolved sources remain
   governed by existing restrictions.
2. **Explicit settled-source preparation.** Existing Pro adds the missing direct
   assertion of a behavior already promised by the draft. Invoke schema-valid
   public `refresh prepare` against exact settled history; require an unambiguous
   non-mutating direction to fresh activation, without a handoff, root substitution,
   or historical rewrite. Specify the structured result and exit behavior in the
   existing planned ADR. This reuses the settled fixture.
3. **Pending-handoff precedence at direct admission.** New Pro adds a focused
   negative case. Settled executions cannot authorize bypassing an outstanding
   transition. Use existing handoff fixtures: unrelated ordinary activation must
   create no target runtime/workflow/lifecycle state and leave the handoff intact;
   preserve exact consumption/replay and inspection routing. Do not blanket-reject
   every operation merely because a handoff file exists. This is a required
   invariant/test, not a newly reproduced product defect.
