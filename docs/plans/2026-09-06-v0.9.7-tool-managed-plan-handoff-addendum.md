## Outcome and bounded correction

The coordinator receives a readable approved plan, without a separate commit,
plan hash, or instruction to manually authenticate its bytes. The current
interface exposes bookkeeping already owned by assignment preparation.
The cheapest direct correction is to derive and check plan identity inside
those existing commands, not add another approval mechanism.

- `assignment prepare` accepts the approved plan path without a caller-computed
  digest or Git commit. It reads the file, derives the digest, and stores a
  fixed snapshot. An approved uncommitted file is a valid input.
- The generated first prompt links to the saved plan with a readable source
  label. Keep the necessary assignment identity and entry instructions, but
  omit separate plan hashes and manual authentication steps.
- Coordinator registration validates the captured snapshot automatically.
  Subsequent source-file edits cannot silently change the assignment;
  a corrupted snapshot blocks startup with an actionable error.
- Keep internal content binding and the existing runtime, integration,
  cleanup, and release checks. Do not migrate or rewrite active assignments.
  Material scope changes still require approval.

## Ownership and verification

The director updates the plan/direct/coordinate skills and assignment brief
reference. The existing coordinator owns CLI, generated prompts, relevant
schema/help/ADR changes, and focused tests. Cover uncommitted input, source
edits after capture, snapshot corruption, and a readable first prompt without
manual plan-checking instructions.

Include this correction in the combined v0.9.7 candidate. Reuse unaffected
evidence and run affected gates; no extra stable release or new test harness.
