## Outcome

An approved assignment can execute locally or with optional workers, preserve its
results, report, obtain director acceptance, close out, and admit its successor
without the director reconstructing protocol state. Interrupted local transitions
resume from exact persisted evidence; ambiguous external actions never replay
blindly. The director remains available for strategic discussion.

Keep the role architecture and necessary lifetime distinctions. Redesign the
affected transitions inside existing modules, not the entire plugin. Deliver one
consolidated successor release rather than publishing the refresh repair first.

## Decisions and simplification boundary

Use one authoritative durable fact per affected transition. Reconcile dependent
records from that fact through existing mechanisms. Separate immutable identity
from observations such as timestamps and from lawful progress.

Before coding, put a short transition map in the existing decision-record
structure: producer fact, consumer, lock/write boundary, replay, and next owner.
Cover local start/completion/dependencies, acceptance/retirement, and resource
reclamation/successor admission. This is a design artifact, not a new registry.

Retain run, assignment, reporting, and resource distinctions where their
lifetimes or permissions genuinely differ. Remove duplicated decisions and
model-transcribed machine facts. A new helper must eliminate a demonstrated
duplication or invalid state, not merely add another abstraction layer.

No database migration, generic recovery/audit engine, extra agent role, daemon,
universal compatibility reader, new dashboard, routing experiment, or telemetry
system. Do not change the user-selected director model or access AGENTS.md.

## Checkpoint 1 — Establish evidence and the transition design

Authenticate the source inputs and working topology. Reproduce each finding
through the nearest public path and classify it as confirmed, already fixed, or
disproved with evidence. Do not force a patch for a disproved finding.

| Finding | Required failing case and durable correction |
| --- | --- |
| F1: local work dependency consumption | Complete actual local A, then derive/start dependent B from A's persisted evidence. Consume coordinator-work authority end to end, without relabeling it or removing the dependency. |
| F2: split-write completion replay | Interrupt after durable completion but before claim transition. Retry authenticates the original caller/evidence and reconciles the claim, preserving result/time and executing no verification command again. |
| F3: later-time start retry | Retry the same start at a different time. Preserve the original identity/timestamp/progress; reject real contract or baseline conflicts. Distinguish fresh start from supported resume. |
| F4: concurrent acceptance | Deterministically interleave two acceptances. Compare state/report inside the existing lock; same-report retries converge, different reports conflict, terminal states cannot be overwritten, and the original acceptance time remains. |

Inspect the immediate producers, consumers, and replay paths together, including
acceptance's neighboring cancellation/retirement updates. Do not declare adjacent
paths defective without evidence. Keep host operations outside long-held locks.

Exit: executable reproductions and a concrete transition design. This is the
only diagnosis-only checkpoint; implement the agreed bounded corrections next.
If the design requires broader lifetime/storage changes, stop for one consolidated

## Checkpoint 3 — Prove complete journeys and thin redundant tests

Use existing fixtures and real Git. Assert the execution kind, package entrypoint,
and branch topology that make each case meaningful before asserting success.

1. **Local-only:** prepared assignment → actual local mutation/checks → run
   completion/report → director acceptance → authorized result preservation and
   coordinator closeout/route retirement → next assignment admission. Zero workers.
2. **Mixed:** local A → dependent visible B → receipt/disposition → integration
   on a delivery branch → verification → child-first closeout → reporting,
   acceptance and coordinator closeout → next assignment. Keep primary behind
   delivery initially; preserve the named result owner through all stages.
3. **Interrupted/failed:** interrupt the changed durable boundaries and resume
   through public commands. Exercise a legitimate cancellation/abandonment exit
   and a lawful successor; retained obligations remain explicit blockers rather
   than being erased or relabeled successful.

Keep mutation/no-change, preservation-owner divergence, patch-equivalence where
supported, callback enrichment order, post-run reporting, and installed/runtime
entrypoints in focused variants rather than a Cartesian-product harness. Include
closeout followed by refresh/admission after legitimate checkout reclamation.

Thin demonstrably redundant fixture setup and repeated equivalent success tests
while preserving distinct safety cases. Record suite duration, slowest relevant
groups, and removed duplication using the existing runner. Do not invent a speed
target or reduce coverage merely to lower test count. During development run
affected tests; run the full suite once after the candidate settles, repeating
only evidence invalidated by subsequent changes.

Exit: the connected journeys complete or deliberately reach their tested genuine
blocker, without test-only state repairs or director protocol reconstruction.
