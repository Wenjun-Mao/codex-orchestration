## Consequential decisions and non-goals

- Keep director/coordinator/executor roles, immutable runtime snapshots, exact
  ownership/preservation, quiet reporting, and distinct archive/reclamation facts.
- Share authenticated facts and their required lifetime, not a universal
  `done` flag. Cancellation, resource cleanup, reporting retirement, and successor
  admission retain explicit, potentially different eligibility conditions.
- An abandoned execution may still have unresolved obligations. Neither missing
  files, App idleness, report submission, nor director acceptance proves that
  execution stopped or that resources are disposable.
- Distinguish not-yet-published registration from corruption of a previously
  ready assignment. Preflight predictable conflicts; also support interrupted
  persistence. Preflight alone is not crash recovery.
- Derive repeated machine facts; independently verify actual host observations.
  Do not collapse approved intent, technical breakdown, and observed results.
- Name what each mechanism replaces or what unsupported state it resolves.
  Necessary safety checks need not meet an arbitrary net-LOC reduction target.
- No rewrite, daemon, database migration, generic transaction engine, second
  ownership/registration registry, or version-specific RC rescue command.
- No historical source-state mutation, pilot repository work, model benchmarking,
  new routing research, AGENTS.md access, or unrelated cleanup.

## Checkpoint 3 — Three endings through actual consumers

Upgrade existing journey fixtures rather than build another harness. Use the
packaged/pinned CLI at critical activation, registration, closure, retirement and
successor boundaries; use real local locator handling. Fake only genuinely
external App transport/observations at the typed adapter boundary. Keep focused
library fixtures for pure predicates, races and negative/corruption cases.

1. **Success → useful successor work:** actual local A → dependent visible B
   consuming A's coordinator-work authority → receipt/integration/verification.
   Start with primary behind delivery and preserve results lawfully. Attempt
   premature coordinator cleanup and prove no archive/removal is authorized.
   Then stop execution correctly, accept/report/close out, retire the real locator,
   admit the successor through the public entrypoint, and perform a useful operation.
2. **Interrupted registration → resume or lawful abort:** fault at significant
   persistence boundaries; query status and exercise both continuations with the
   same available runtime and deterministic identities. A genuine persistent
   conflict must allow a lawful failed exit, not require successful retry forever.
   Missing previously published records must remain a different, blocked case.
   Assert that abort accounts for execution, reservations, reporting and resources;
   retained obligations name an authorized owner and executable next action. No
   unexplained active obligation may be hidden behind a cancelled assignment.
3. **Same assignment refresh → failure → cancellation:** keep the assignment open
   across authenticated refresh. Exercise the selected retirement policy: remove
   the source namespace after retaining sufficient authenticated evidence elsewhere,
   or retain necessary source evidence until its last consumer. Terminate replacement
   execution, then cancel that same assignment. Preserve completed work and account
   for remaining obligations before successor admission. Verify evidence/resources
   become eligible for retirement at the intended point, not retained indefinitely.

Assertions include side-effect counts, original replay identity/time, changing
baselines, actor authority, source/target runtime distinctions and next-consumer
success. Neither worktree disappearance nor registration alone is the endpoint.
Do not substitute cancellation-before-refresh for ending 3, or baseline extension
with no dependency for the mixed A-to-B proof.

An independent reviewer checks the joint design and final tests for success-path
fixture repairs, skipped consumers, weakened conditions, and hidden new machinery.
Retain existing zero-child coverage; no additional live canary is required for it.
Run focused checks while changing code. Run the settled full suite with actual
terminal exit/summary; reuse only evidence unaffected by later changes. Report
durations and measured savings honestly, including regressions or absent savings.
