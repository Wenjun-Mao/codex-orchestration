## Standing release-consolidation rule

Implementation checkpoints are not mandatory public releases. When approved
unreleased work is superseded by a later candidate and nobody needs the
intermediate distribution, retain reviewable commits and necessary RCs, skip
intermediate stable tagging/publishing/installing, and ship one final useful
candidate. Do not widen scope merely to batch work or indefinitely delay a
needed correction. Already published/tagged artifacts remain immutable;
active run snapshots never hot-switch. In this case v0.9.5 is already
published, so the combined correction targets v0.9.6, not a rewritten v0.9.5.

Run focused checks as each change lands. Share unchanged evidence only within
its exact applicability; run full combined gates once the final candidate is
ready. Repeat affected checks after relevant changes and every failed live
segment. Necessary RC installation/reload and exact stable artifact checks
are not disposable intermediate release ceremony.
