## Checkpoint 1 — One installed identity contract

Define one pure rule distinguishing exact source release identity from its
supported installation metadata. Use it in CLI admission, refresh skill
authentication and refresh target validation. Keep source/tag validation strict.

- Package/runtime version remains the semantic release authority and namespace.
- Installed plugin version may be that exact version or that version with one
  prescribed, bounded `+codex.<cachebuster>` suffix. Preserve its full raw value
  as distribution evidence; never strip arbitrary metadata or accept a different
  base/prerelease version. Confirm syntax against the actual update helper.
- Do not weaken package names, payload/runtime hashes, loaded-skill identity or
  exact tagged-source checks. Distinguish source validation from distribution
  validation rather than maintaining contradictory ad hoc comparisons.
- Replace the test that treats the prescribed cachebuster as an error. Exercise
  the installed fixture through the real CLI and correct refresh skill, beyond
  `--version`, and through refresh target validation. Include stamped/unstamped
  success and wrong-base, malformed-suffix, wrong-skill and altered-payload
  rejection at the authority layer responsible for each protection.
- Reuse existing fixtures and the installation helper; no new installer service,
  registry, version counter or metadata migration.

Exit: all identity consumers agree, and a distribution-shaped fixture executes
the normal read-only admission route without a metadata contradiction. Validate
this before any real installation or user restart. Record a concise ADR.

## Checkpoint 2 — One closeout driver, representative tests

Confirm `closeoutIteration` has no supported production consumer beyond the
tests found by the audit. Check repository exports, CLI, package docs and
declared integration surface; do not contact pilots or assume all exported
functions are private. A supported external consumer requires disposition before
removal, not a silent compatibility shim.

- Map the 17 old-path tests to unique invariants and their owning-host-path
  replacements. Preserve child-first ordering, ambiguity/no replay, concurrent
  closeout, exact result preservation, dirty/shared/protected worktree rejection,
  attachment drift and resumable archive/reclamation.
- Port unique cases to `closeoutIterationWithOwningHost` or its shared pure
  checks; remove only redundant scenarios and then the unused old driver.
- Split oversized assignment fixtures so reporting/pure-state tests do not
  create a live executor and multiple Git worktrees unnecessarily. Keep real
  Git for tests whose subject is Git ownership, integration or cleanup.
- Share immutable fixture inputs only; preserve per-test mutable isolation.
  Keep intentional timeout coverage where it proves real process behavior.
- Retain one CLI-backed finish → accept → archive/reclaim → next-assignment
  journey and the focused v0.9.9 recovery regressions. Exercise the actual
  owning-host prepare/result/reconcile sequence rather than only library mocks.

Exit: one runtime closeout driver; every removed test has a documented retained
protection; affected tests pass. Record changed test-file timing and fixture
setup reductions. No blind concurrency increase, blanket mocks, global caches,
timeout inflation, or arbitrary LOC/runtime reduction target. If runtime does
not improve, explain the measured tradeoff rather than claiming optimization.
